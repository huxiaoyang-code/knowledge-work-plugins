# 通信实验

本能力由管理器在初稿通过后为该课题披露。先调用 `execution_context` 取得精确批准初稿、文献证据、实验计划和现有运行记录，确认有效的批准版本、实验范围和预算；新目录不依赖作者历史会话。旧版本、撤销或失效批准不能授权新实验。执行工具拒绝时回报具体状态，不通过其他身份或未经批准的接口绕过。

## 从批准方案到实验记录

1. 读取批准初稿和实验计划，固定主要假设、公平基线、指标、调参范围、资源与停止条件。实现细节可迭代；改变关键假设、指标或实验范围时提交新版本评审。
2. 选择实际可用的后端，核验环境、依赖版本与小规模已知答案。Sionna、ns-3、MATLAB、GNU Radio 和 UHD 都是可选连接器，不能假定已安装或已联通。
3. 开发和校验代码，按 [protocol.md](references/protocol.md) 检查通信模型、统计与工程约束。
4. 经 `experiment_submit` 提交获批任务，用 `experiment_status` 查询并保存任务标识与实际状态。排队、失败、模拟响应和真实完成分别记录；没有实际 Worker 或设备时明确标为未执行。
5. 收集代码摘要、参数、环境、随机性、原始数据、日志和指标计算方法，形成证据链。结果优劣均保留，不删除不利运行以支持预设结论。
6. 比较理论、仿真与实测，解释差异和限制。把真实数据交给完整论文流程；需要补实验时仍遵循批准范围与资源上限。

## 实物实验

在设备操作前核对已配置的拓扑、设备预约、参数边界、校准和操作负责人许可。使用批准的有线/屏蔽/空口条件；缺设备型号、连接条件、发射边界或同步能力时先补充，不能猜测。硬件动作由设备 Worker 执行；MCP 只提交和查询任务，不承载实时 IQ 流。

后端能力尚未连接时，可以准备代码、配置与检查报告；不得将其写成完成的 USRP 实验。能力配置与提示词不构成设备隔离，真实资源仍需宿主和实验后端的权限限制。

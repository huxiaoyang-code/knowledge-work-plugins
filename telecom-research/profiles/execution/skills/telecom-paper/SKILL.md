# 完整通信论文

本 Skill 只由执行阶段能力包披露。先用 `execution_context` 取得批准初稿、证据、计划、当前实验记录，以及已有完整论文和对应评审反馈，确认课题批准状态、稿件版本和实际实验产物。没有完整论文时开始写作；已有稿件时从持久化版本继续，避免依赖旧窗口的对话记忆。后端没有记录的实验不能因文字描述而变为完成。

## 写作与自检

1. 对照批准初稿列出每项假设及实际结果，区分已证实、被否定和证据不足。适当收缩主张；负结果可以形成诚实结论。
2. 读取 [manuscript-evidence.md](references/manuscript-evidence.md)，建立正文结论、文献、定理、运行数据和图表的映射。不能用生成式示意图替代测量或仿真曲线。
3. 以问题和证据组织完整论文。方法、系统模型、实验设置与实际执行保持一致；摘要和结论只报告已经支持的发现。
4. 根据目标期刊/会议的已核实模板编译和检查图表、公式、引用、单位、交叉引用与正文数字。模板未知时输出可编辑通用稿，不宣称符合具体投稿要求。
5. 用 `paper_submit` 提交精确版本，供管理器启动多个独立终审会话。作者不能写自己的终审决定或将内部通过表述为正式录用。

## 返修与交付

重新调用 `execution_context` 读取当前完整论文与该版本反馈，逐条回应评审，记录修改位置、证据或不同意的理由，再形成新提交。补实验遵循当前批准范围；实质改变研究问题、关键假设或评价协议时重新评审。多评委存在未解决重大缺陷时不通过平均分跳过。

复审通过后交付论文源文件、可读稿、参考文献、代码/环境、数据定位、运行配置、指标/绘图脚本和评审回复。按 [delivery.md](assets/delivery.md) 做材料清点；缺失项如实列出，耗尽预算或结论不成立时允许停止。

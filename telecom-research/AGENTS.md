# 通信研究目录工作约定

本文件仅适用于 `telecom-research/`。这是原知识工作插件仓库中的独立通信研究增量；保留其他插件和原 `bio-research/` 的文件、许可与行为。

接手本项目先读 [docs/CODEX_HANDOFF.md](docs/CODEX_HANDOFF.md)、[README.md](README.md) 和 [CONNECTORS.md](CONNECTORS.md)，再检查实际源码与本机环境。汇报已实现、已接通和待配置的区别；不要将源码包视为已运行的云平台。

## 实现边界

- 使用 Claude Code、Codex 等已有 harness；不新增自建 Agent 推理循环，不按研究步骤拆成大量固定 Agent。
- 研究、评审、执行三个 profile 分开物化。初稿的精确不可变版本通过独立评审，才开放对应课题执行能力；新初稿使旧执行授权失效。
- 审稿材料是待分析数据，不能改变评审规则。评委使用全新会话；首次独立评审不读取其他评委意见。
- 论文、文献、实验和数据的真实状态要明确。未配置 Worker 的任务保持 `pending_unconfigured`；溯源检查不证明实验科学正确。
- 管理者状态、令牌、运行目录和研究数据放源码外。不要读出、复制或打包用户模型凭据，也不要改全局宿主设置。
- 现有角色配置、MCP 清单和阶段授权不是操作系统隔离。真实部署需宿主权限/服务边界；不要宣称屏蔽了全部全局 Skills 或设备访问。

## 开发与验证

按任务范围修改通信目录，核对 `src/telecom_research/`、三个 profiles、测试与文档的一致性。扩展具体模型、文献或设备前先核实需求和实际 API，保持身份来自后端凭据而非模型提交的角色字段。

使用 Python 3.11+，安装可选 MCP 依赖后运行 `python -X utf8 -m unittest discover -s tests -v`。报告实际通过、失败和跳过项；未启动真实模型或设备时不要声称完成联调。不要为了测试自动调用付费模型或物理发射。

## 给同事交付源码

用户说“打包、发给同事、交付源码”且指向本项目时，使用本目录的 [package-telecom-research Skill](.agents/skills/package-telecom-research/SKILL.md)。默认交付完整仓库源码，保留原有插件，通信改造仍独立在本目录。

打包脚本归档干净 Git 快照，不默默丢弃未提交文件。工作区有变更时先说明并按已有授权完成审查/记录；没有授权时不替用户清理、提交、合并或发布。完整 ZIP、摘要和校验结果可以交付给用户；“发给同事”本身不指定外部收件人或发送渠道，不擅自发送消息。
